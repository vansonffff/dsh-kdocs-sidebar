## 0.2.6 — 2026-09-13

本版是**表现层迭代**：右栏从「功能完整的插件界面」做成「DSH 原生的云文档浏览器」，
并修掉了若干真实缺陷 —— 其中两个在**已发布的 0.2.0 里就会让用户踩到**。

**改动面很窄**：`src/` 与 0.2.0 **几乎逐字节相同**，唯一例外是 `src/tools.js`
里那两个工具输出契约的修复（见下）。Host、CLI 调用、资源协议、Agent 工具的能力面均未变化。

### ⚠️ 从 0.2.0 升级的人请先看这一条

**0.2.0 发布的 `kdocs_list` 与 `kdocs_search` 是坏的 —— 两个分页工具的输出契约都写反了。**

工具的 `output.schema` 会被编译成 JSON Schema，并对每次返回值做**致命校验**：
多一个未声明的字段、或少一个必填字段，都会抛 `INVALID_TOOL_OUTPUT`，
`render` 根本不会执行。0.2.0 的情况是：

| 工具 | 0.2.0 的声明 | 0.2.0 实际返回 | 后果 |
|---|---|---|---|
| `kdocs_list` | 要求 `pageCount` 必填 | `{ entries, total }` | **每一次列目录都失败**，空文件夹也一样 |
| `kdocs_search` | 把 `total` 声明为**必填** | `{ entries, pageCount }` | 没要云盘总数的搜索失败；**要了总数的仍然失败**（多带了一个未声明的 `pageCount`） |

也就是说：**如果你的 Agent 在 0.2.0 上一调用 `kdocs_list` / `kdocs_search` 就报错，那是这两个 bug，不是用法问题、也不是登录问题。** 升级到 0.2.6 即修复。

0.2.0 的测试套件里没有任何用例检查过编译后的 schema，所以这两个契约断裂当时没被发现。
现在由 `test/tool-contract.test.js` 用运行时的 `validateJsonSchemaValue` 直接校验，
并由 `test/tools-runtime.test.js` 对着真实运行时再验一遍。

### 新增

- **文件类型图标**：文件夹 / Word / Excel / PowerPoint / PDF / 文本 / 图片 / 通用，
  8 种字形，统一 16×16 包围盒，只使用产品自身的颜色 token。
  文件名认不出来的后缀一律落到「通用」——认不出来就该长得像文件，而不是像 Word。
- **行内快捷操作**：鼠标悬停或键盘聚焦文件行时，行尾出现 `···`，点击打开与右键相同的菜单。
  它绝对定位、不参与布局，所以**不会挤掉文件名**；宽度不足时仍可继续用右键，是渐进增强而非唯一入口。
- **键盘可达性与无障碍**：行、视图标签、菜单项都有 `focus-visible` 焦点环；
  图标按钮带 `aria-label`（如「更多操作：专项法律服务合同.docx」）；装饰性图标 `aria-hidden`；
  视图标签使用 `role="tablist"` / `aria-selected`。

### 改进

- **信息密度提升**：行高 29px → 24px，顶部工具区 118px → 89px。
  **同一屏可见文件从 23 行增至 30 行。**
- **顶部导航去胶囊化**：六个视图入口从 9 个带边框的胶囊改为纯文字 + 下划线选中态。
  附带修掉一个 0.2.0 就存在的缺陷：窄侧栏下视图标签会**换行成两行**（占 57px）；
  现在任何宽度都保持一行（核心控件不再从一行变两行）。
- **搜索区压缩**：`全部 / 文件名 / 正文` 从独占一行三个胶囊改为搜索框内的行内控件。
  **搜索能力一项未减**（三种范围全部保留），搜索逻辑一行未改。
- **右键菜单精修**：菜单项统一 28px 高，7 项按功能分成 3 组（两条 0.5px 极弱分割线），
  按「简洁、安静、接近桌面应用原生菜单」的方向调整；**未增加任何图标**。
- **预览工具栏精修**：`原版 / 文本` 合成一个分段控件（视图模式），
  `引用到对话` 与 `在金山文档打开` 保持独立动作按钮 —— 两类控件的视觉权重因此可区分。
  **整体高度未增（实测 42px → 40px）**，且结构保持单行。
- **深色模式一致性**：面板内所有颜色改为产品设计 token，深浅两套主题实测一致；
  仅金山文档自身 iframe 的页面底色保留白色（那是文档的颜色，不是我们的 chrome）。
- **移除「网页登录」入口**（应读者要求）。该入口会在侧边栏内打开金山文档主页，
  用于桌面端「原版」视图的应用内会话登录。整条链路（按钮、页面、tab 类型、文案）已移除，
  **不残留无法打开的僵尸类型**。若将来需要，恢复步骤记录在
  `docs/MILESTONE-0.2.5-UI-POLISH.md`。
- 预览工具栏的「↻ 刷新」保留，且改为自己的文案（原名沿用了已删除页面的键）。

### 修复

- **文件行悬浮导致整个面板变白**（本版开发期引入并当场修复）。
  行的快捷按钮引用了作用域外的翻译函数，鼠标一进入文件行就抛
  `ReferenceError`，抛在 React 协调子组件阶段，槽位运行时随即清空整个面板。
  **根因不是那一行，而是三处结构性漏洞**：测试的 React 替身让 `useState` 永远返回初值
  （该分支在 CI 里从未执行）、有一条断言只检查「源码里存在某段文本」（写坏的和写对的文本一模一样）、
  以及 `guarded()` 当时只是 `try/catch` 而非真正的 React 错误边界（子组件的错不经过它）。
  三个漏洞都已修复，并新增真渲染测试与变异验证。
- **搜索状态下点击视图标签，看到的是空搜索页而不是该视图**。
  视图数据其实已取回，但渲染仍走搜索分支。
- **文件夹重命名会丢掉 `.v1` 这类点后缀**。草稿按正则剥「扩展名」，
  但写回时只有文件才带扩展名可补 —— 于是 `案件.v1` 被改成 `案件`，**静默改掉你的文件名**。
  现在只对真正带扩展名的条目做剥离。
- **分页失败后无法重试**。视图与搜索的「加载更多」失败时会把游标丢掉，
  而该按钮只在有游标时渲染 —— 一次瞬时网络失败就再也加载不了，且无法恢复。
  现在失败时保留游标（首页失败仍清空）。
- **修复一条恒真的测试**：live 分页用例断言 `pages >= 1`，任何运行都通过；
  已收紧为 `> 1` 并追加「确实读到了首页之外的条目」。

### 内部质量（不改变行为）

- 测试 **207 → 252**，全部通过。
- 发布前由独立模型做了一次全仓审查，含 **19 条承重测试的变异验证**
  （故意破坏实现，确认恰好相关测试失败）。审查记录、仍未修项与理由：
  `docs/MILESTONE-0.2.5-UI-POLISH.md`。
- 间距收敛到统一刻度（2/4/6/8/12/16），清掉了 `5px / 7px / 9px` 这类随手数值。

### 已知问题（本版未修，将在后续版本处理）

1. **`getLink` 失败时「在金山文档打开」/「复制链接」静默无反应**（应给出错误提示）。
2. **tab 标题组件没有错误边界**（面板主体已有）——标题抛错的后果是标签空白。
3. **预览组件的 effect 依赖了整个 props 对象**，依赖「座位引用稳定」这一假设才不出问题。
4. **无法解析的地址在「原版」模式下是一块白**（错误信息目前只在文本模式显示）。
5. **`unwrapData` 不检查内层 `code`**：若 CLI 返回嵌套错误信封，会被当成成功静默吞掉。
   该形状实测从未出现，但属于潜在风险。
6. **预览与标题组件仍无测试执行到**的部分：错误分支、划选引用、`needsLogin` 分支、
   详情/历史版本/批注结果渲染。

## 0.2.0 — 2026-09-11（npm 上此前的版本）

从 0.1 到 0.2：把金山文档从「能看」做到「能用」。

- **引用进对话**：面板与预览都能把文档写入输入框（`dsh-resource://` 地址），划选一段可带摘录。
- **Agent 可直接读**：`kdocs_read` / `kdocs_stat` 接受资源地址或分享链接，4 个只读工具。
- **右键直接干活**：7 项菜单（引用 / 打开 / 复制链接 / 详情 / 历史版本 / 正文批注 / **重命名**）。
  注：重命名是本插件唯一的写入操作。
- **五个云盘视图**：星标 / 最近 / 共享给我 / 我分享的 / 回收站。
- **搜索强化**：类型、扩展名、时间范围、总数（`withTotal`）。
- **面板位置记忆**、**加载更多**、**工具卡片**、**首页直达链接**。
- 关闭 0.1 评审 13 项中的 12 项。

完整记录见 `docs/MILESTONE-0.1.md` 与 `docs/MILESTONE-0.2.md`。

## 本文件的核对方式

```bash
# 取回已发布的 0.2.0，与本次发布的 tarball 逐文件对比
mkdir -p /tmp/cmp && cd /tmp/cmp && npm pack dsh-kdocs-inside@0.2.0
tar -xzf dsh-kdocs-inside-0.2.0.tgz
# 再解开新版本的 tarball 到 /tmp/new，然后：
diff -r /tmp/cmp/package /tmp/new/package
```
